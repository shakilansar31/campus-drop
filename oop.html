CORE JAVA ARCHITECTURE

Object-Oriented Programming & Data Structure Principles

CampusDrop is built on clean Core Java OOP fundamentals and standard Collections (HashMap, LinkedList, Stack, Queue). Below is a complete breakdown of code architecture and viva references.

The 4 Pillars of Object-Oriented Programming

OOP PILLARS
1. ENCAPSULATION Item.java

Data Hiding & State Integrity

State variables (id, name, status, location) are declared private to prevent unauthorized direct field mutation. Access is exposed strictly via public getter and setter methods. 

public class Item {
    private int id;
    private String status;

    public String getStatus() { return status; }
    public void setStatus(String status) { 
        this.status = status; 
    }
}
2. ABSTRACTION CampusDrop.java

Hiding Operational Complexity

Hiding complex collection manipulation mechanics behind simple interface methods. Callers invoke submitClaim(...) or returnItem(...) without needing to manage queue pointers or linked list node links. 

public class CampusDrop {
    private HashMap<Integer, Item> items;
    private Queue<ClaimRequest> claimQueue;

    public boolean submitClaim(int id, String name) {
        claimQueue.offer(new ClaimRequest(...));
        return true;
    }
}
3. POLYMORPHISM Override

Method Overriding

Overriding standard Java java.lang.Object behavior. The toString() method is overridden in Item and ClaimRequest to supply custom formatted table outputs dynamically. 

@Override
public String toString() {
    return String.format("| %-5d | %-20s | %-8s |", 
        id, name, status);
}

The 4 Mandatory Java Data Structures

DATA STRUCTURES
1. HASHMAP

HashMap<Integer, Item>

Stores items in key-value pairs using unique Integer Item ID as the key. Provides constant time complexity O(1) for searching, inserting, and updating items without linear scanning.

2. LINKEDLIST

LinkedList<Item>

Stores history log of returned items (recoveryHistory). Preserves exact chronological order of property recovery with O(1) tail appends.

3. STACK

Stack<String>

Implements system Undo functionality following Last-In-First-Out (LIFO) semantics. Every operation pushes an action string; clicking Undo pops the top action.

4. QUEUE

Queue<ClaimRequest>

Manages item claim requests in First-In-First-Out (FIFO) sequence using offer() and poll() to guarantee fair claim evaluation.
