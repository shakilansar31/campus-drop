CORE JAVA ARCHITECTURE Object-Oriented Design & Collections Framework

Object-Oriented Programming & Data Structures Guide

CampusDrop is implemented in Core Java applying strict OOP principles and the Collections Framework (HashMap, LinkedList, Stack, Queue), backed by an Oracle SQL Database via DAO (Data Access Object) classes.

The 4 Pillars of Object-Oriented Programming

OOP PILLARS
1. ENCAPSULATION model/Item.java

Data Hiding & Controlled Access

Member variables (id, name, status, location) are marked private to prevent arbitrary direct external mutation. Internal state is manipulated strictly via public getters and setters. 

public class Item {
    private int id;
    private String status;

    public String getStatus() { return status; }
    public void setStatus(String status) { 
        this.status = status; 
    }
}
2. ABSTRACTION CampusDrop.java

Hiding Internal Complexity

Complex collection manipulations and database transactions are abstracted behind clean service methods. Callers invoke submitClaim(...) or returnItem(...) without managing low-level pointers. 

public class CampusDrop {
    private HashMap<Integer, Item> items;
    private Queue<ClaimRequest> claimQueue;

    public boolean submitClaim(int id, String name) {
        claimQueue.offer(new ClaimRequest(...));
        return true;
    }
}
3. POLYMORPHISM @Override

Method Overriding & Representation

Overrides base java.lang.Object behavior. The toString() method is overridden across models (Item, ClaimRequest) to output formatted representations for console logging. 

@Override
public String toString() {
    return String.format("| %-5d | %-20s | %-8s |", 
        id, name, status);
}
4. CLASS & OBJECT Instantiation

Blueprint vs Memory Realization

A class serves as a blueprint defining state fields and methods. An object is a concrete instance allocated in JVM memory with specific member variable values. 

// Blueprint: Item.java
Item laptop = new Item(
    101, "Dell Inspiron", "Electronics", 
    "Library", "25/09/2026", 
    "Rahul", "LOST", "ACTIVE"
);

Core Java Collections Utilized

COLLECTIONS
1. HASHMAP

HashMap<Integer, Item>

Stores items in key-value pairs using unique Item ID as the key. Delivers constant time O(1) lookup, insertion, and retrieval.

2. LINKEDLIST

LinkedList<Item>

Preserves sequential history of returned items. Guarantees chronological order of recovery transactions with O(1) tail appends.

3. STACK

Stack<String>

Implements system Undo functionality following LIFO (Last-In, First-Out) semantics. Operations push actions to the stack; undo pops the top action.

4. QUEUE

Queue<ClaimRequest>

Dispatches student claim requests in FIFO (First-In, First-Out) order via offer() and poll() for fair administrative review.
